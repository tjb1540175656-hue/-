# Draw Inline / 正文自动配图

手机 Termux 酒馆用的本地前端扩展。AI 在**正常回复正文**写 `<draw>英文画面提示词</draw>`，文字回复完成后，扩展调用酒馆现有的生图扩展，最后把图片插回这处标记并请求保存聊天。

**不需要 Gemini 中转支持工具调用。不注册工具、不调用函数工具、不直连 ComfyUI。**

## 你现在的工作流不用重做

- 在酒馆原来的「图像生成 / Image Generation」设置里继续选择 **ComfyUI**，使用你已经导入并选中的 **my 工作流**。
- ComfyUI 地址继续用 `http://192.168.31.167:8188`；这是手机酒馆的生图后端设置，不填到本扩展，也不填到 Gemini 中转地址。
- 模型、LoRA、负面提示词、采样器、尺寸等都由酒馆现有配置和你的工作流决定，本扩展不替换它们。
- 「工作流/API 格式 JSON」属于酒馆现有生图配置；本压缩包是另一回事——**识别正文标记的前端扩展**。不要把扩展文件当工作流导入，也不用再把工作流放进扩展目录。
- 扩展只传递 `<draw>` 中的提示词。如果原工作流没有正确接收酒馆的正面提示词占位符，图片不会自动随故事变化；那是工作流连接问题，而不是要更换模型或 LoRA。

## 手机本地安装（不需要 GitHub）

1. 把 `draw-inline.zip` 复制到手机的 **Download** 下载目录。
2. 在 Termux 找到你**实际运行的那个酒馆根目录**：里面应有 `server.js`、`package.json` 和 `public`。不要装到电脑上的酒馆，也不要误装到另一个旧酒馆目录。
3. 将压缩包解压到该酒馆根目录下的 `public/scripts/extensions/third-party/`。压缩包已经带有顶层 `draw-inline` 文件夹。

例如（`~/SillyTavern` 只是例子，必须换成你的实际目录）：

```sh
cd ~/SillyTavern
mkdir -p public/scripts/extensions/third-party
unzip -n /sdcard/Download/draw-inline.zip -d public/scripts/extensions/third-party
```

若 Termux 提示没有共享存储权限，先按你手机的方式授予存储访问权限，或把 zip 手动复制进 Termux 可读的目录。没有 `unzip` 时也可用文件管理器先解压，再复制文件夹。

安装后目录必须是：

```text
实际酒馆根目录/
└─ public/scripts/extensions/third-party/draw-inline/
   ├─ manifest.json
   ├─ index.js
   ├─ README.md
   ├─ TEST_RESULTS.md
   └─ tests/mock.test.mjs
```

不能多套一层变成 `draw-inline/draw-inline/manifest.json`。

4. **刷新手机浏览器中的酒馆页面**；必要时强制刷新以清理旧脚本缓存。通常不需要重启酒馆。
5. 打开扩展设置，找到 **Draw Inline / 正文自动配图**，勾选「启用」（默认启用）。失败后可点「重试最后一条」。这里没有需要填的 API 密钥。

安装过程只新增这个独立文件夹，不要求修改酒馆源码或手动编辑配置。运行时开关会正常保存到酒馆扩展设置，成功图片与去重状态会保存在聊天数据中。

## 给 AI 的规则

把下面这段加到你实际使用的提示词/角色规则中即可，**不要求开启函数工具**：

```text
正常继续故事，不要只输出图片提示词。
当这条回复需要展示画面时，在你希望插图出现的位置输出：
<draw>English visual description of this scene</draw>
每条回复最多输出一处 <draw>...</draw>。
标签必须放在最终回复正文，不放在思考过程、代码块或反引号里。
标签内只写英文画面描述，不写命令、宏或解释，不超过 4000 字符。
不需要画面时，不输出 draw 标签。
```

例如最终 AI 正文：

```text
她推开窗户，清晨的光落在书桌上。
<draw>a quiet room at dawn, open window, sunlight on a wooden desk, soft cinematic lighting</draw>
远处传来了鸟鸣。
```

扩展会在中间插入图片，保留前后故事。请先等文字生成完成，再等图片完成，避免中途继续、重抽或编辑原消息。

## 行为与重试

- 只自动处理启用后**新生成、已完成**的 AI 回复，不扫描聊天历史，不处理用户/系统消息、开场白或生图扩展自己发出的消息。
- 流式生成期间不扫描 token；兼顾 `GENERATION_ENDED` 在 `MESSAGE_RECEIVED` 前或后的顺序。中止文字生成不会自动配图。
- 每条回复的**当前 swipe 版本最多 1 张**；第二处标签会原样保留，不再生成。重抽出来的新版本可配自己的 1 张。
- 任务全局排队串行，每条消息有生成锁；连续点重试不会重复提交。
- 失败保留原 `<draw>`，扩展设置显示简短错误；不会自动无限重试。点「重试最后一条」会处理当前聊天最后一条 AI 回复的当前版本，也可手动用于历史消息。
- 提示词为空、超过 4000 字符、带 `{{...}}` 宏或仅为 `you/me/scene/raw_last/last/face/background` 时不生成。请改成完整画面描述后手动重试。
- 只读取 `message.mes`，不读取 `extra.reasoning`；忽略常见 `<think>/<thinking>/<analysis>/<reasoning>` 思考块和代码示例。自定义的特殊思考分隔符不能保证识别，请把标记放在最终正文。
- 切换聊天、删除/编辑/切换原消息版本或关闭开关时，在途结果不会插到其他消息里；切走再切回也不复用旧任务。继续/重抽开始后会作废旧任务。需要时回到原消息手动重试。
- 取消插入不等于取消 ComfyUI 已排队的计算，可能仍消耗一次生成。已经保存进画廊但没有插入的图片也不会自动删除。
- 成功使用标准 Markdown 图片写回正文，并同步当前 swipe 文本与 `extra.draw_inline` 去重元数据；不设置 `extra.image/media`，不替换整条消息的图片渲染方式，不清理用户已有附件。
- 如其他扩展写了 `extra.display_text` 显示缓存，本扩展会安全拒绝处理该消息，不删除缓存或覆盖其他扩展的数据。移除冲突后再手动重试。

## 实现依据与兼容范围

**参考并核对的本地源码：SillyTavern 1.18.0。手机版本未知，不能保证任意旧版/魔改版可用。**

该版本 `stable-diffusion/index.js` 的 `generatePicture()` **没有导出**；工具实现会正常发送生图消息，不适合直接拿来做内联插图。因此本扩展取得 `getContext().SlashCommandParser.commands.sd` 中**酒馆原生注册的 `/sd` 回调**，直接以参数对象调用：

```js
callback({ quiet: 'true', extend: 'false', edit: 'false' }, prompt)
```

- `quiet=true`：禁止原生生图消息发送回调，仍保存生成文件并返回图片 URL。
- `extend=false`：不另请 LLM 扩写提示词，避免回到 Gemini 工具/额外文本生成问题。
- `edit=false`：不弹出提示词编辑器。
- 后两项是 `/sd` 内部临时选项，由酒馆回调自己的 `finally` 恢复；不永久更改你的原设置。酒馆已有正/负面前缀及其他扩展的 SD 提示词处理钩子仍可能影响最终提示词。
- **没有把 AI 文本拼成 `/sd ...` 命令再解析**，所以提示词中的 `|`、斜杠、引号不会执行成其他命令；宏被拦截，图片地址仅取自原生回调结果，并校验/转义后写入 Markdown。

需要 `SillyTavern.getContext()`、事件总线、生成开始/结束与消息接收/变更事件、`saveChat()`、`updateMessageBlock()`、原生 `/sd` 注册表与上述参数。缺少核心接口时显示安全停用；缺少原生生图回调/参数时保留标记并提示失败，不尝试猜测接口或直连 ComfyUI。使用传统前端模块加载方式，无需新版 manifest hooks。

限制：

1. 先保证酒馆原本的图像生成功能已启用、来源为 ComfyUI、选中了你的工作流。若原生生图本身不能用，本扩展也不能修复它。
2. 本扩展只保证**自己的**生图任务串行，不和酒馆手动生图或其他生图扩展共享互斥锁。配图期间不要同时手动生图、改生图设置；同一聊天也不要同时开多个活跃客户端自动配图。
3. 使用酒馆标准保存接口。1.18.0 的 `getContext().saveChat()` 内部会吞掉部分服务器保存错误，扩展只能报告「已请求保存」，无法独立证明落盘；留意酒馆原生保存失败通知，保存失败时不要立刻关闭页面。
4. 扩展本身不输出提示词/密钥到错误状态，但酒馆原生生图扩展原有的控制台日志和错误通知不受本扩展控制。不要公开包含密钥或私人提示词的原生日志。
5. 没有超时后自动重提机制，以免一个仍在运行的 ComfyUI 任务被重复提交。长时间无响应请查看原生生图进度或停止按钮，不要反复刷新重试。

测试命令（有 Node 即可，不用安装依赖）：

```sh
node --test tests/mock.test.mjs
```

可选：指定 `ST_SOURCE_ROOT` 为本地酒馆根目录，额外运行源码契约测试。不设置该环境变量时，该项会明确跳过。详细本次结果见 `TEST_RESULTS.md`。

**没有实际生成图片，没有调用 ComfyUI `/prompt`，没有启动/重启服务，没有修改参考酒馆源码/配置，也没有自动安装到电脑酒馆。** 手机浏览器实际显示、你选中的工作流是否收到提示词、ComfyUI 联通及最终图片效果，需要你在手机端安装后确认。

## 停用/卸载

先取消勾选开关。卸载时只移走你安装的 `public/scripts/extensions/third-party/draw-inline` 文件夹，再刷新页面；不要删除聊天、工作流或酒馆其他目录。已经保存到聊天正文的 Markdown 图片不会因卸载消失。
